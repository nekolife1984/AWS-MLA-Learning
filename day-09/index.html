Machine Learning — Lesson 09

データの偏り（バイアス）と
SageMaker Clarify

偏ったデータで学習したモデルは、偏った判断をします。だから学習の前に「データの偏り」を数値で測る。今日はその道具、SageMaker Clarify と学習前バイアスの指標を押さえます。

# バイアス検出# 公平性# 説明可能性（SHAP）
⚖️

一言で言うと

SageMaker Clarify は、学習データに潜む偏りを数値で測り、モデルが不公平な判断をしないかを事前にチェックできるサービスです。

01

Clarify ができること ― 設定から運用連携まで

ステップをタップすると、各場面で Clarify が何をしてくれるかが切り替わります。中心は「学習前」と「学習後」の2回のチェックです。

› › ›
02

図解：「件数は同じ」でも「採用率」は違う

CI と DPL の違いを、採用データの例で見てみましょう。この区別が今日の山場です。

例：採用の合否データ。グループA・グループB ともに 1,000 件ずつあるが、採用された割合は A が 80%（800件）、B が 40%（400件）だったとします。

CI が見るもの：データ件数

グループごとの「人数・件数」のバランス

グループA1,000件
グループB1,000件

✅ 件数はぴったり同じ → CI は小さい（偏りなし）

DPL が見るもの：採用された割合

グループごとの「好ましいラベル（採用）」の割合

グループA の採用率80%（800件）
グループB の採用率40%（400件）

⚠️ 採用率に 40 ポイントの差 → DPL = 0.8 − 0.4 = 0.4 で大きい

つまり、件数がそろっていても、結果（ラベル）の割合が偏っていればバイアスありです。「何件あるか」を見るのが CI、「どれだけ有利な結果になっているか」を見るのが DPL。この切り分けが試験でもクイズでも問われます。

03

学習前バイアスの代表指標 ― CI・DPL・CDDL 比較表

3つの指標は「何の偏りを見るか」が違います。略称と「見る対象」のペアで覚えるのがコツです。

指標何の偏りを見るか計算のイメージ値の読み方
CIClass Imbalance（クラス不均衡） データ件数の偏り
グループ（facet）ごとに、データが何件ずつあるか		 件数の多いグループと少ないグループの件数差を、合計件数で割ったもの 0 に近いほど件数が均等。絶対値が大きいほど、特定グループのデータが多すぎる／少なすぎる
DPLDifference in Proportions of Labels（ラベル割合の差） ラベル割合の偏り
グループごとに「好ましいラベル（採用・承認など）」が付いた割合		 グループA の好ましいラベルの割合 − グループB の好ましいラベルの割合（例：0.8 − 0.4 = 0.4） 0 なら割合に差なし。絶対値が大きいほど、一方のグループだけが有利な結果になっている
CDDLConditional Demographic Disparity in Labels（条件付きのラベル格差） 条件を揃えたときのラベル格差
学歴・職種・経験年数など他の条件で層別（グループ分け）したうえでのラベル割合の差		 同じ条件の層（ストラタム）ごとに DPL のような割合の差を測り、全体として集計したもの 0 に近いほど条件を揃えても格差なし。全体では差が見えなくても、層別すると偏りが隠れている場合に検出できる

🔑 覚え方：CI ＝ Count（件数）、DPL ＝ Label の割合、CDDL ＝ Condition（条件）を揃えた DPL。問題文が「件数・データの分布」なら CI、「割合・率の差」なら DPL、「条件を揃えて・層別して」なら CDDL です。

04

試験で問われるポイント

MLA-C01 では、指標の意味に加えて「Clarify を使う前提」と「対策のタイミング」が問われます。

1

facet と label の指定が必須

Clarify のバイアス分析では、注目する属性 facet（例：性別・年齢層などの列）と、予測対象 label（例：採用／不採用の列）の指定が必須です。さらに「どのラベル値が好ましい結果か（favorable outcome）」も設定します。この2つを決めないと、グループ間の比較そのものが成立しません。

2

バイアス対策は「学習前」が基本

偏りはデータの段階で生まれます。学習が終わってから気づいても、モデルはすでに偏りを覚えた後です。だから対策の基本は学習前のデータで見つけて直すこと。Clarify の学習前バイアス測定はその入り口で、見つけた偏りはデータの追加収集やバランスの取り直しなどで人が対処します。

3

学習後は「予測の偏り」＋「SHAP で説明可能性」

学習後にも Clarify は使えます。モデルの予測結果にグループ間の偏りがないかを測るほか、SHAP 値で「どの特徴量が予測にどれだけ効いたか」を示す説明可能性（explainability）レポートを出せます。「なぜその予測になったか説明したい」という要件が出たら SHAP／Clarify です。

05

間違えやすい！混同しやすいポイント

引っかけの定番は「CI と DPL の取り違え」と「Clarify が直してくれるという誤解」です。

CI（Class Imbalance）

見るのはデータの件数。グループごとに何件のデータがあるか、その偏りを測る。

VS

DPL（ラベル割合の差）

見るのは好ましいラベルの割合。件数が同じでも、採用率などに差があれば大きくなる。

🔑 見分け方：問題文が「件数・データ数・分布の偏り」なら CI、「採用率・承認率など割合の差」なら DPL です。

SageMaker Clarify

偏りを測って数値とレポートで示すツール。検出と可視化が仕事です。

VS

データの修正・対策

偏りを直す作業そのものは Clarify の担当外。追加収集やリサンプリングなどの対処は人が行う。

🔑 見分け方：Clarify は「測るだけ。自動修正はしない」が大原則。「Clarify が自動でバイアスを取り除く」という選択肢は誤りです。

SageMaker Clarify

担当はバイアスと説明可能性。学習前・学習後のチェックを、分析ジョブやレポートとして実行する。

VS

SageMaker Model Monitor

担当は本番運用中の監視。デプロイ済みモデルのドリフトや品質低下を継続的に見張る。

🔑 見分け方と連携：Model Monitor と Clarify を組み合わせると、運用中のエンドポイントでもバイアスや SHAP による説明を継続チェックできます。「運用中に偏りを監視したい」なら両者の連携が答えの候補です。
