Machine Learning — Lesson 05

Amazon Athena と
AWS Lake Formation

S3 に置いたデータを、その場で SQL で調べる Athena。そして「誰に・どこまで見せるか」を一元管理する Lake Formation。データレイクの「調べる役」と「守る役」をセットで押さえます。

# サーバーレス# 標準SQL# データレイク# ガバナンス
💡

一言で言うと

Athena は S3 のデータをサーバーレスで SQL 検索するサービス、Lake Formation はデータレイクの権限をまとめて管理するガバナンスの仕組みです。

01

図解 ― クエリが結果を返すまで

ステップをタップすると、各段階の役割が切り替わります。データは S3 に置いたまま動かさないのがポイントです。

› › ›

💰 コストは「読んだ量」で決まる

Athena の課金はスキャンしたデータ量ベースです。読み込む範囲を絞るほど、そのまま安く・速くなります（下はイメージ図です）。

CSV を全件スキャン 100%
日付でパーティション分割 約45%
Parquet 化 ＋ パーティション 約15%

※ 割合は概念を伝えるための目安です。実際の削減幅はデータやクエリによって変わります。

02

何ができる・いつ使う？

役割は真逆に近い2サービスです。「調べたい」なら Athena、「見せ方を管理したい」なら Lake Formation と覚えましょう。

🔍 Amazon Athena

役割：S3 のデータを「調べる」

S3 に置いた CSV・JSON・Parquet などのファイルを、サーバーやクラスターを用意せず、標準 SQL でその場で調べられます。

  • アドホックな調査（「とりあえず中身を見たい」）
  • ログ分析や集計のスポットチェック
  • ML 学習前のデータ確認（分布・欠損のチェック）
サーバーレス課金はクエリした分だけ標準SQL

🛡️ AWS Lake Formation

役割：データレイクを「守る・管理する」

Glue Data Catalog を中心に、データベース・テーブル・カラム・行レベルまで細かく権限を管理できます。

  • LF-Tags を使えば、タグ単位で権限をまとめて管理できる
  • S3 のバケットポリシーや IAM ポリシーをばらばらに書かずに済む
  • 「部署 A にはこのカラムだけ見せる」といった統制が可能
細粒度の権限管理LF-Tagsガバナンス
03

試験で問われるポイント

MLA-C01 では、Athena の課金モデルと、Lake Formation の権限の細かさが繰り返し問われます。

1

Athena はサーバーレス ＋ スキャン量課金

課金はクエリでスキャンしたデータ量ベースです。パーティション分割と、Parquet などカラムナー（列指向）形式への変換で、スキャン量とコストを減らせます。「Athena のコストを下げたい」という問題は、ほぼこの2つが答えです。

2

テーブル定義は Glue Data Catalog、実データは S3

Athena のテーブル定義（スキーマ情報）は Glue Data Catalog に置かれます。ここがひっかけポイントで、テーブルを削除しても S3 の実データは消えません。定義と実体が別物だという理解が問われます。

3

Lake Formation はセルレベルまでの細粒度制御

権限はデータベース・テーブル・カラム・行・セル レベルまで細かく設定できます。しかもその権限は Athena・Glue・EMR・Redshift Spectrum といった統合エンジンで共通に効きます。「カラム単位で見せ分けたい」→ Lake Formation が鉄板の答えです。

04

間違えやすい！似たものとの違い

Day 4 の Glue との関係が最大のひっかけポイントです。「クエリする／変換する／守る」で切り分けましょう。

Amazon Athena

S3 のデータをクエリするもの。SQL で読み取って答えを返すだけで、データ自体は書き換えません。

VS

AWS Glue

データを変換・ETL するもの。形式を変えたり、整形したりして、別のデータを作り出します。

🔑 見分け方：Athena 自体は ETL しません。「Parquet に変換したい」なら Glue、「Parquet を検索したい」なら Athena です。変換してから検索する、という組み合わせもよく出ます。

AWS Lake Formation

データの権限とガバナンスを管理するもの。「誰が・どこまで見られるか」を決める役目です。

VS

データの移動・変換サービス

Glue の ETL や Kinesis など、データを運んだり形を変えたりするサービス群の役割です。

🔑 見分け方：Lake Formation はデータを移動・変換するサービスではありません。データは S3 に置いたまま、アクセス権だけを一元管理します。
サービスひとことで言うと覚えるキーワード
Amazon Athena S3 のデータをサーバーレスで SQL 検索する スキャン量課金 ／ Parquet ＋ パーティションで節約
AWS Glue データの変換・ETL とカタログ管理を行う ETL ／ Data Catalog ／ クローラー
AWS Lake Formation データレイクの権限を細かく一元管理する カラム・行・セルレベル ／ LF-Tags
