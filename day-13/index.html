Machine Learning — Lesson 13

SageMaker Training Jobs と分散学習

Day 12 で選んだアルゴリズムを、実際にどう学習させるか。今日は Training Job の流れ、データの渡し方（入力モード）、そして複数 GPU で学習を分担する分散学習の2方式を押さえます。

# Training Jobs# FastFile# データ並列 / モデル並列# スポット学習
🏋️

一言で言うと

SageMaker Training Jobs は「学習スクリプトとデータを渡すだけ」で、インスタンスの用意から学習の実行、モデル成果物の保存まで面倒を見てくれるマネージド学習です。

01

Training Job の流れ

データは S3 から入り、学習済みモデルは S3 へ、メトリクスは CloudWatch へ。SageMaker が間に入ってインフラを全部引き受けます。

🪣 Amazon S3 TRAINING DATA

学習データをチャネル（入力口）ごとに渡します。train / validation など名前を付けて、最大20チャネルまで指定できます。

›
⚙️ SageMaker Training Job MANAGED TRAINING
  • アルゴリズム：組み込み or 自作コンテナ
  • インスタンス種別・台数を指定
  • インスタンスの用意〜実行〜片付けは SageMaker が担当
›
📦 成果物 OUTPUT

学習済みモデルは S3 に保存され、そのまま推論などに使えます。

📊 メトリクスは CloudWatch へ ― 学習中の損失や精度などの指標が自動で送られ、進み具合を監視できます。
🧹 終われば自動で終了 ― 学習が終わるとインスタンスは解放されるため、起動しっぱなしの課金が起きません。
▶ 学習の開始方法：SageMaker Python SDK の estimator.fit()、または API の CreateTrainingJob を呼び出すだけです。
02

入力モードの比較：File / Pipe / FastFile

「S3 のデータを、学習インスタンスへどう届けるか」が入力モードです。データの大きさと読み方で選び分けます。

入力モードINPUT MODE 仕組みHOW IT WORKS 向いている場面BEST FOR 注意点NOTE
File既定のモード S3 から全データをインスタンスのストレージにダウンロードしてから学習を開始する データがディスクに収まり、何度も繰り返し読む場合 データが大きいほど、ダウンロードの待ち時間が長い
Pipeストリーミング S3 から名前付きパイプ経由でストリーミング配信する 学習をすぐ始めたい場合。EBS 容量も小さくてよい 古い方式で、新規は FastFile が推奨される流れ
FastFile大きいデータに推奨 S3 を POSIX ファイルシステムとして見せ、必要な分だけオンデマンドで読み込む 大きいデータでもダウンロード待ちなしで学習を始めたい場合 S3 プレフィックスのみ対応（マニフェストファイルは非対応）
データソースとリージョン データソースは S3 のほか EFS / FSx for Lustre も選べます。ただしデータは学習ジョブと同じリージョンに置く必要があります。
分散学習でのデータ配布 ShardedByS3Key でデータをインスタンス間で分割して渡せます。一方 FullyReplicated は全インスタンスに全データを渡します。
03

分散学習の2方式：分けるのはデータか、モデルか

複数 GPU で学習を分担する分散学習には2つの方式があります。見分け方はシンプルで、「何を分割するか」だけです。

DATA PARALLEL

データ並列分けるのは「データ」

モデルを各 GPU にコピーし、データを分割して並行学習する方式。データが大きい・学習を速くしたい場合の基本形です。

GPU 1 ・ モデルデータ 1/3
GPU 2 ・ モデルデータ 1/3
GPU 3 ・ モデルデータ 1/3
⇅ 勾配を AllReduce で同期してパラメータを更新
  • 各 GPU が担当分のデータで勾配を計算し、AllReduce で同期してパラメータを更新します。
  • SageMaker の分散データ並列ライブラリ SMDDP が、AWS のネットワークに最適化された AllReduce / AllGather を提供します。
  • オープンソースでは PyTorch DDP / torchrun / MPI なども使えます。
MODEL PARALLEL

モデル並列分けるのは「モデル」

モデル自体を複数の GPU に分割する方式。1つの GPU のメモリに載らない巨大モデルのための手段です。

GPU 1モデルの層 1〜8
GPU 2モデルの層 9〜16
GPU 3モデルの層 17〜24
→ 1つのモデルをリレーのように受け渡して計算
  • モデルが大きすぎて1つの GPU に入りきらないときに、層やテンソル単位で分割して載せます。
  • SageMaker のモデル並列ライブラリ SMP が、シャーディング・パイプライン・テンソル並列などを提供します。
⚠️ 間違えやすいポイント モデル並列は「速くするための手段」ではありません。モデルが1つの GPU に入らないときの手段です。データが大きいだけなら、選ぶのはデータ並列です。
04

マネージドスポット学習：安く学ぶには条件がある

EnableManagedSpotTraining を有効にすると、スポットインスタンスで学習できます。ただし「中断されても再開できる」設計が前提です。

最大 約90% コスト削減

AWS によれば、スポットインスタンスを使うことで学習コストを最大で約90%削減できます。その代わり、インスタンスが中断される可能性がある点を受け入れる必要があります。

CHECKPOINTチェックポイントが前提

学習途中の状態を保存し、中断後にそこから再開できるようにします。既定の保存先 /opt/ml/checkpoints/ は S3 に同期されます。

MaxWaitTimeInSeconds待ち時間の設定

スポット枠を待つ時間を含む総待ち時間です。MaxRuntimeInSeconds（学習の最大実行時間）以上に設定します。

MaxRuntimeInSeconds実行時間の上限

学習そのものにかけられる最大時間です。スポットでは「待つ時間＋学ぶ時間」が収まるよう、2つの値の関係に注意します。

05

試験で問われるポイント

今日の内容は「使い分け」と「見分け方」がそのまま問題になります。3つの型で押さえましょう。

1

入力モード3つの使い分け

File は全データをダウンロードしてから開始、Pipe はストリーミング、FastFile は必要な分だけオンデマンド読み込み。大きいデータなら FastFile / Pipe、とくに新規では FastFile が推奨、という流れで答えます。

2

データ並列とモデル並列の見分け方

判断軸は「分けるのはデータか、モデルか」。データが大きくて速くしたいならデータ並列（SMDDP）、モデルが1つの GPU に載らないならモデル並列（SMP）です。

3

スポット学習はチェックポイントとセット

スポットは安い代わりに中断がありえます。だからこそ、チェックポイントを S3 に保存して再開できることがセットで問われます。MaxWaitTimeInSeconds ≧ MaxRuntimeInSeconds もあわせて確認しましょう。
