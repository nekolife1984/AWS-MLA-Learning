SageMaker Autopilot と JumpStart

「ゼロから作らない」ための2つの近道。Autopilot はデータを渡すだけでモデル作りを自動化する AutoML、JumpStart は学習済みモデルをそのまま使えるモデルハブです。

# AutoML# 学習済みモデル# ノーコード
💡

一言で言うと

Autopilot は「自分のデータからモデルを育てる」自動化、JumpStart は「できあいのモデルを持ってくる」カタログです。

どちらも、モデル作りの出発点を短くするための仕組みです。向きの違いを押さえるのが今日のゴールです。

01

Autopilot と JumpStart の違い

まずは全体像を表でつかみます。「自分のデータから作る」のか「できあいのものを使う」のかが最大の分かれ目です。

観点 SAGEMAKER AUTOPILOTAutopilot SAGEMAKER JUMPSTARTJumpStart

主な対象 分類・回帰（表形式データ） 画像・テキスト・基盤モデルなど幅広いタスク

02

Autopilot の流れ

ステップをタップすると、各工程で何が起きるかを確認できます。人がやるのは最初と最後だけです。

03

JumpStart でできること

JumpStart は「モデルとテンプレートのカタログ」。ゼロから作らず、選んで使うのが基本の使い方です。

📚 学習済みモデルをそのままデプロイ

数百の学習済みオープンソースモデルがカタログに並んでいて、選ぶだけですぐにデプロイして使い始められます。

🎛️ 基盤モデルのファインチューニング

基盤モデルを選び、自分のデータでファインチューニングしてから使うこともできます。「できあい」を土台に、自社向けに寄せる使い方です。

🧩 ソリューションテンプレート

よくあるユースケース向けのソリューションテンプレートから、モデルだけでなく必要なインフラごと立ち上げられます。

⚙️ 組み込みアルゴリズムの活用

組み込みアルゴリズムを、自分の学習ジョブに使うこともできます。カタログは「完成品モデル」だけの置き場ではありません。

04

試験で問われるポイント

シナリオ問題では、要件のキーワードからどちらを選ぶかが問われます。

1

「コードを書かずに自動で作りたい」→ Autopilot

「コードを書かずに、自分のデータから自動でモデルを作りたい」と聞かれたら Autopilot（AutoML）が答えです。

2

「学習済みモデルを素早く使いたい」→ JumpStart

「学習済みモデルを素早くデプロイ／ファインチューニングしたい」と聞かれたら JumpStart が答えです。

3

Autopilot の特徴は「透明性」

自動で作るだけではありません。何をしたかが分かる候補定義ノートブックと説明レポートが生成され、中身を確認できます。

4

Canvas の裏側では Autopilot が動いている

SageMaker Canvas はコードを書かずに使える画面（UI）で、その裏側でモデル作りを担っているのが Autopilot です。

05

間違えやすい点

似たもの同士の区別と、自動化への過信。この2点が定番の引っかけです。

SageMaker Autopilot

「自分のデータからモデルを育てる」。材料（データ）は自分で用意し、作る工程を自動化する。

VS

SageMaker JumpStart

「できあいのモデルを持ってくる」。すでに学習済みのものを選んで使う。

🔑 見分け方：2つは向きが逆です。「作る」なら Autopilot、「持ってくる」なら JumpStart。

SageMaker JumpStart

基盤モデルを、自分の SageMaker アカウント内にデプロイして自分でホストする。運用も自分の管理下に置く。

VS

Amazon Bedrock

基盤モデルをサーバーレス API として呼び出すだけ。ホスティングは AWS 側に任せる。

🔑 見分け方：どちらも基盤モデルを扱えます。違いは「自分でホストするか（JumpStart）、API で呼ぶだけか（Bedrock）」です。
⚠️

Autopilot は万能ではない

自動化できるのはモデル作りの工程までです。データの品質を保つこと、目的の列を正しく指定すること、結果を業務にどう活かすかの判断は、人の仕事として残ります。
