一言で言うと

Glue はコードで ETL を回す「データ整備の職人」、DataBrew はノーコードでデータをきれいにする「ビジュアルツール」。この一文が今日の結論です！

図解：データが整うまでの流れ

生データが「分析・学習できるデータ」になるまでの定番パイプラインです。この流れ自体が試験に出ます。

クローラーが「型」を読み取り、カタログに登録してから変換する

ポイントは真ん中の Data Catalog。データのスキーマ（列名や型などのメタデータ）を一元管理する場所で、後段の Athena や SageMaker はここを参照してデータを使います。

04

試験で問われるポイント

MLA-C01 では「どのサービスを選ぶか」の判断が問われます。この3つを押さえればバッチリです。

1

クローラーと Data Catalog の役割

クローラー はデータソースを走査してスキーマ（列名・型）を自動で推論し、Data Catalog にメタデータとして登録します。このカタログが、Athena のクエリや SageMaker の学習データ参照など、あらゆる後段処理の「起点」になるのが重要ポイントです。

2

「バッチETLは Glue、対話的準備は DataBrew」

Glue は Spark ベースなので大規模データの定期バッチ処理が得意。DataBrew はノーコードで画面を見ながら試行錯誤する対話的なデータ準備が得意。「大量・定期・自動化」なら Glue、「すぐ試したい・コードなし」なら DataBrew、と使い分けましょう。

3

DataBrew のレシピは「再利用＆定期実行」できる

DataBrew で作った変換手順は レシピ として保存でき、別のデータセットにも使い回せます。さらにレシピをジョブ化すれば、新しいデータが来るたびに同じクリーニングを定期実行できます。「手作業の手順を自動化できる」のがレシピの本質です。

05

間違えやすい点・似たものとの違い

名前が似ていて混同しやすいペアを2つ。ここは試験の「ひっかけ」ポイントですよ、マネちゃん！

DataBrew と SageMaker Data Wrangler 混同注意

どちらもノーコード寄りのデータ準備ツールですが、所属が違います。DataBrew は Glue ファミリーの独立サービスで、主な対象はデータアナリストなど幅広いユーザー。一方 Data Wrangler は SageMaker Studio の中にある機能で、ML エンジニアが学習データを作るためのものです。

覚え方：「汎用のデータ準備は DataBrew、SageMaker の中で完結させるなら Data Wrangler」です。

Glue と Athena 混同注意

どちらも Data Catalog を使うのでセットで出てきますが、役割は正反対に近いです。Glue はデータを「変換する（ETL）」もの。Athena は S3 上のデータを SQL で「クエリする（問い合わせる）」もので、データそのものを変換・加工して書き出すことはしません。

覚え方：「整えるのが Glue、眺めて調べるのが Athena」。詳しくは次回 Day 5 で扱います！
