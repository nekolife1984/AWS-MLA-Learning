データ準備から学習・デプロイ・運用まで。機械学習の「全工程」を1つの場所で回せるサービス、それが SageMaker です。今日はその地図を頭に入れましょう。

# フルマネージド# MLプラットフォーム# ライフサイクル
💡

一言で言うと

Amazon SageMaker は、データ準備から学習・デプロイ・運用まで、機械学習の全工程をまとめて面倒見てくれるフルマネージドなサービスです。

01

MLライフサイクル ― 4つの工程

工程をタップすると、対応する SageMaker の機能が切り替わります。まずはこの流れ自体を覚えるのが近道です。

› › ›
02

いつ SageMaker を選ぶ？

キーワードは「モデルは作りたい。でもサーバー管理まではしたくない」です。

✅ SageMaker が向いている場面

  • 自分たちのデータで、独自のモデルを作って学習させたい
  • 学習用のコンピューティングや環境構築を AWS に任せたい
  • 学習から推論・運用までを一貫して管理したい

🧭 自前で組む場合との違い

EC2 上に自分で ML 環境を構築すると、ライブラリの管理、スケーリング、可用性まで全部自分で面倒を見る必要があります。SageMaker はそのインフラ部分を引き受けるマネージドな ML プラットフォームです。

03

試験で問われるポイント

MLA-C01 のシナリオ問題では、「状況 → どの機能か」を結びつける力が試されます。

1

SageMaker ＝ マネージドな ML プラットフォーム

EC2 に自分で環境を組む手間を省ける、という位置づけが大前提。「インフラ管理を減らしたい」という要件が出たら SageMaker が有力候補です。

2

工程と機能名の対応を覚える

Data Wrangler＝データ整形、Ground Truth＝ラベル付け、Training Jobs＝学習、エンドポイント＝推論、Model Monitor＝運用監視。この対応がシナリオ問題で頻出です。

3

推論方式の使い分け

「学習済みモデルを API で呼びたい（1件ずつ・すぐ答えがほしい）」→ リアルタイムエンドポイント。「大量データをまとめて推論したい」→ バッチ変換。この切り分けは鉄板パターンです。

04

間違えやすい！似たものとの違い

名前が似ている・役割が近いサービス同士の区別は、試験の定番の引っかけポイントです。

Amazon SageMaker

自分でモデルを作って・運用する場所。学習データも学習方法も自分で用意する。

VS

Amazon Bedrock

完成済みの基盤モデルを API で使う場所。モデル自体は作らず、既存のものを利用する。

🔑 見分け方：「モデルを学習させる必要があるか？」→ あるなら SageMaker、ないなら Bedrock を検討。

Amazon SageMaker（全体）

ML プラットフォームサービス全体の名前。準備・学習・デプロイ・運用のすべてを含む。

VS

SageMaker Studio

SageMaker の中の開発環境（IDE）の名前。ノートブックなどで開発作業をする画面のこと。

🔑 見分け方：Studio は「作業する場所（道具）」、SageMaker は「サービス全体」。Studio ⊂ SageMaker の関係です。
