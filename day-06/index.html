特徴量エンジニアリングの基礎
スケーリング・欠損・外れ値

モデルに渡す前の「データの下ごしらえ」が今日のテーマです。数値の尺度をそろえ、カテゴリを数値に変え、欠けた値と飛び抜けた値を処理する——この4つの基本技を押さえます。

# スケーリング# エンコーディング# 欠損値# 外れ値
💡

一言で言うと

特徴量エンジニアリングとは、生データをモデルが学びやすい形に整える作業のことです。良いモデルも、入力データが整っていなければ力を発揮できません。

01

4つの整形テクニック

各テクニックをタップすると、要点と使い分けが切り替わります。まずは全体像をこの4つで押さえましょう。

› › ›
02

比較表で整理する

「どっちを使うか」の判断軸を表にまとめました。試験ではこの使い分けそのものが問われます。

スケーリング：Min-Max正規化 vs 標準化

どちらも「数値の尺度をそろえる」処理ですが、変換の仕方と向く場面が違います。

観点Min-Max正規化標準化（Zスコア）
変換式 (x − min) / (max − min) (x − 平均) / 標準偏差
変換後の範囲 0〜1 の範囲に収まる 平均 0・標準偏差 1（範囲は決まらない）
外れ値の影響 大きい。1つの外れ値で全体が潰れる 比較的受けにくい
向く場面 範囲を 0〜1 にそろえたいとき、画像のピクセル値など 分布が正規分布に近いとき、多くのMLアルゴリズムの既定の選択肢

エンコーディング：カテゴリの種類で選ぶ

カテゴリ変数を数値に変える方法は、「順序があるかどうか」で決まります。

変数の種類使う手法例・注意点
名義変数
（順序なし）		 One-Hotエンコーディング 都道府県、血液型など。カテゴリごとに 0/1 の列を作る
順序変数
（順序あり）		 順序エンコーディング 満足度（低=0、中=1、高=2）など。順序の情報をそのまま活かせる
名義変数に
ラベル付け		 ラベルエンコーディング（要注意） 東京=0、大阪=1、福岡=2 のような番号付け。モデルが「福岡は東京の2倍」のような存在しない順序・大小関係を誤解する恐れがある
高カーディナリティ
（種類が多すぎる）		 頻度でまとめる／ターゲットエンコーディング等 郵便番号やユーザーIDなど。One-Hotにすると列が爆発的に増えるため、レアなカテゴリを「その他」にまとめるなどの工夫が要る
03

試験で問われるポイント

MLA-C01 では「どのモデルに・どの前処理が要るか」の組み合わせがシナリオ問題で問われます。

1

スケーリングが効くのは「距離ベース・勾配ベース」のモデル

k-NN、SVM、k-means のような距離ベースのモデルと、線形回帰・ロジスティック回帰・ニューラルネットワークのような勾配ベースのモデルでは、スケーリングの有無が精度と学習の安定性を左右します。逆に決定木系（ランダムフォレスト、XGBoost など）は分岐を値の順序だけで決めるため、スケーリングは基本不要です。

2

補完・変換のパラメータは「学習データだけ」で決める

欠損値を埋める平均値や、標準化の平均・標準偏差は、学習データからだけ計算し、それを検証・テストデータに適用します。全体のデータで計算すると、テストデータの情報が学習に漏れるデータリーケージになり、評価が実際より良く見えてしまいます。

3

エンコーディングは「順序の有無」で選ぶ

順序のない名義変数は One-Hot、順序のある変数は 順序エンコーディング。名義変数にラベルエンコーディングを使うと、モデルが番号の大小を意味のある順序と誤解する点が定番の引っかけです。

4

AWS では Data Wrangler / Glue DataBrew が前処理の担い手

SageMaker Data Wrangler や AWS Glue DataBrew には、スケーリング、エンコーディング、欠損値補完といった変換が組み込みで用意されています。「コードを書かずに前処理したい」という要件と結びつけて覚えておきましょう。

04

間違えやすい点

「やってしまいがちな処理」と「正しい処理」の対比で確認します。

❌ 名義変数にラベルエンコーディング

都道府県に 東京=0、大阪=1、福岡=2 と番号を振る。モデルが「2 は 0 より大きい」という実在しない順序関係を学習してしまう。

VS

⭕ 名義変数は One-Hot

カテゴリごとに 0/1 の列を分けるので、順序の誤解が生まれない。順序がある変数だけ順序エンコーディングを使う。

🔑 見分け方：そのカテゴリに「どちらが大きい」と言える順序があるか？ なければ One-Hot が基本です。

❌ 全データで補完値を計算

学習データとテストデータを合わせた全体の平均値で欠損を埋める。テストデータの情報が学習側に漏れるデータリーケージが発生する。

VS

⭕ 学習データだけで決めて適用

補完値・標準化の平均と標準偏差は学習データのみから計算し、検証・テストデータにはその値をそのまま適用する。

🔑 合言葉：「fit は学習データだけ、transform は全部に」。この原則はスケーリングにも欠損補完にも共通します。

❌ 決定木系にも念のためスケーリング

ランダムフォレストや XGBoost にまで標準化をかける。害はないが効果もなく、処理と管理のコストだけが増える。

VS

⭕ モデルに合わせて取捨選択

決定木系は値の大小の順序だけで分岐するのでスケーリング不要。距離・勾配を使うモデルに絞って適用する。

🔑 見分け方：そのモデルが特徴量同士の「距離」や「勾配」を計算するかが、スケーリング要否の判断軸です。
